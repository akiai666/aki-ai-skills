# Aki IP 角色素材包

将用户提供的人物图片或视频转成可复用的两套角色素材。支持任何明确的目标人物，不默认套用 Aki 的脸、性别或红外套。

最少一张清晰正脸即可开始；45°、侧脸或转头视频有助于还原。穿搭可选填，其他设置自动完成。

## 默认交付

直接完成写实版和可爱 3D 卡通版，内部检查形象后继续扩展，不额外等待用户确认。用户明确要求预览、单一风格或局部修改时，以用户范围为准；单一风格用完整双风格目录中的另一风格标为暂缺，不替用户生成额外资产。

每种风格包含 8 张独立生成的 PNG：面部特写；全身正面、90°侧面、背面；上半身正面、45°、90°、背面。面部/上半身请求 1024×1024，全身请求 1024×1536。完整默认交付是 16 张原图、两套总览、两组全身三视图、两组上半身四视图、总入口 HTML、两张独立风格 HTML、离线 ZIP、提示词与来源记录。

先交付可直接用于视频的单图，再从同一批单图拼总览。不能只给一张总览，也不能把低分辨率裁切或插值放大说成高清原图。

## 执行顺序

1. **确认路径与范围。** 使用当前项目或用户指定目录，输出到 `output/imagegen/<角色名>/<新版本>/`。新版本使用日期时间或递增编号，不覆盖已有版本。目录素材默认递归读取支持的文件，跳过隐藏文件和符号链接；不要把已有输出目录当作输入目录。
2. **准备参考。** 按 [workflow.md](references/workflow.md) 运行 `prepare`。读取联系表，再查看原始清晰参考；视频每条均匀抽取最多 36 帧。选择角度互补的图片，在 `sources.json` 标记选择结果、角度、镜像/遮挡/模糊情况，保留时间戳。
3. **记录身份。** 用 [identity-and-prompts.md](references/identity-and-prompts.md) 写简短 `identity.md`：可见的脸型、眉眼、鼻唇、发型、配饰、体态和服装。区分事实与补全；不能把文字特征提取当成已运行的人脸算法。多个人物且目标不明确，或所有画面都无法辨认，才询问用户。
4. **锁定正面。** 先生成写实特写，再将它和真人图共同用于写实全身正面。内部目视检查后继续。卡通特写与正面以真人参考及写实形象为共同依据。参考照片优先保持身份，生成锚点统一服装与风格。
5. **逐角度生成。** 每次调用生成一个独立视角，同时携带真实相近角度与该风格的正面锚点。正面、45°、90°、背面必须真正改变方向；全身和上半身统一使用人物朝画面左侧的侧面方向。不得用水平镜像冒充另一个观察角度。
6. **检查并修正。** 对照真人参考检查辨识度、眼镜、年龄、头身比例、发型、衣服、手脚、角度一致性。全身图另以原始像素查看脸部裁切，检查眉眼、眼镜和嘴是否清楚且与特写一致；不能仅凭整图尺寸判定脸部清晰。每张有明显问题的图最多针对性修正一次；记录实际模型、渠道、尺寸、提示词、参考图和检查结果。失败图不阻塞其他可完成素材，交付时标出缺项。
7. **构建交付。** 填写 `manifest.json` 后运行 `build`、`verify`。只有全部通过才能称完整高清包；仍有问题则运行 `build --draft` 生成明确标注的待完善版本。总览缩略图允许缩小排版，独立原图不改像素。用可用的桌面打开工具展示总入口 HTML，最终给出 HTML 和 ZIP 路径。

## 生图通道

通过宿主技能目录发现并读取 `imagegen`。先运行 `bun scripts/doctor.ts`（视频加 `--video`）检查本地依赖；工具可用性和模型权限由 Agent 检查实际工具及一次真实生成结果，doctor 不代表模型连通。缺依赖时按当前系统安装；没有可用生图渠道时明确说明，不能交付占位图。

默认模型为 GPT Image 2。优先内置工具，先让本地参考图通过 `view_image` 进入上下文；只有路径或文字描述不算传入参考图。确认工具能满足模型与多参考要求。内置工具不要求 API key。

若当前会话已明确授权 CLI/API 路线，沿用授权，通过 `imagegen` 自带 CLI 调用 GPT Image 2。没有授权且内置工具不可用时，说明缺项并按 `imagegen` 规则处理。用户已明确要求该路线时不反复确认。禁止自行编写 SDK runner、修改系统 imagegen 脚本、静默改用 Gemini 或其他模型/服务商。

凭证只从宿主统一配置读取，不进脚本、仓库、日志或素材包。路由配置只记录非敏感渠道名，CLI 参数不要包含真实密钥。按实际工具记录模型信息，无法确认时说明，不能把未知内置模型声称为已验证 GPT Image 2。

## 视觉约束

- 写实优先像本人，保留真实眉眼、鼻形、嘴唇、脸颊、自然不对称和年龄线索，避免模板帅脸、磨皮、过度瘦脸。
- 卡通默认可爱 3D 动画质感，保留成年辨识度与接近成年人的比例；避免四头身、大头矮身。儿童等特殊主体以实际年龄和用户要求为准。
- 发型来自参考，保留自然疏密、碎发和不规则走向，避免等距重复粗发束、塑料条、拖把感。不照搬照片镜像、彩色环境光或广角畸变。
- 衣服按用户指定，其次采用主要参考图的服装；未知下装用深色长裤和简洁运动鞋，并写入补全说明。不能默认所有人穿 Aki 红外套。
- 浅灰背景、柔和光照、自然表情，无图内文字与无关道具。全身站姿头脚完整、双手放松且结构清楚；正侧背面保持同一服装、配饰、身高与头部尺度。
- 缺少侧面或背面参考时允许补全，在 HTML 的参考说明中标记，不声称为实拍还原。

## 局部修改与旧版保留

用户说只改脸、头发或服装时，先读取指定旧版和新参考，沿用其他全部资产。创建新版本，不重生成整个人物。

针对允许区域建立蒙版，先目视检查覆盖范围，再按 `imagegen` 编辑流程获得候选图；使用 [workflow.md](references/workflow.md) 的 `composite` 仅合入该区域。候选图必须与原图尺寸和位置一致，不盲目拉伸对齐。API 透明蒙版和本地灰度混合蒙版语义不同，不能混用。

验证区域外像素不变、旧文件哈希不变，并目视检查接缝及眼镜等跨边界结构。修改单图后从新版单图重建总览；若旧版只有低清裁图，不放大伪装高清，保留并标记限制。新版 HTML 设置相对历史入口；旧版 HTML 和图片保留。ZIP 只携带当前版本，离线页面不放不可用的历史链接。

## 验证边界

辅助脚本验证文件、尺寸、格式、链接和像素不变量，不能自动证明“像本人”或“角度正确”。这些必须查看图片。Skill 创建或维护时运行 `bun test`、`bun run check` 和系统 skill-creator 的格式校验。可用现有图片回归验证 HTML/ZIP，无需为测试重复付费生成整套；未实际运行的生成步骤要如实说明。
