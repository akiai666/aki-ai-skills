# 网页动作视频接入

用户提供的视频可作为可复用角色动作。浏览器端生成、下载与额度规则依当次授权执行；本 Skill 不自动调用收费视频服务。

1. 以相同身份图作为起始参考，保持镜头、全身比例、地面和背景固定。普通动作包括准备、执行、收势；不把多个不同动作塞进一个片段。背景色与角色衣物、眼镜区分，先验证三类代表动作。
2. 保存原始视频及提示词。用 ffprobe 检查时间戳、时长、分辨率和帧数；容器声称 60fps 不代表有 60 个独立姿势。
3. 在整个片段上使用同一裁切窗口与抠像参数。检查头发、眼镜、手指、白鞋和衣服在浅色与深色背景上的边缘，不逐帧紧裁、拉伸或重定位角色。
4. 按时间戳导出固定帧率透明 PNG 序列，例如 24fps 的5秒片段应有120帧。帧率重采样不等于运动补帧。MP4 可用作预览；需要透明播放时另交 alpha WebM，但工程合成优先用 PNG 序列。
5. 按 [actions.md](actions.md) 注册 `actions`：记录 fps、frames、固定 anchor、站立 bodyHeight、来源与验收状态。没有标定无缝循环时不添加 loop。
6. 视频如果没有逐帧手部追踪，设置 `contactSupported: false`、`annotationStatus: "untracked-not-for-prop-contact"`、`events: []`。兼容协议所需 hands 只能作为占位，不是实际接触点。人物可独立播放，卡片/桌子/图解单独布置；`characterPoint()` 会明确拒绝这些素材。静态姿势也可使用同一标记。
7. 先以 `--allow-draft-actions` 创建本地评审工程，检查真实讲解画面。不要因为文件齐全就升级 approved。完整播放、慢放与抽帧结果分开报告。

```tsx
<AkiCharacter action="wave" actionSince={0} actionSpeed={1} x={420} y={840} h={610}/>
```

30fps 工程会根据时间轴从24fps动作中选取来源帧，文字动画可以独立按30fps运作。角色不需要逐帧与每个字匹配；动作起点、重点姿势与口播语义相符即可。精确拿卡、放下等接触则必须先补真实手部坐标与事件。

离线图库宜用缩略图和视频按需播放，暂停时才载入指定 PNG。不要进入页面就并行加载所有动作的全部帧；静态代表图与连续动作必须分别标注。
